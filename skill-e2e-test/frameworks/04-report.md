# 04 — E2E 报告（格式 / 问题清单 / skill-evolution 接口）

> 本文件是 SKILL.md「流程④ E2E 报告」的操作细则，不独立成立。

## 一、报告结构

```
## E2E 报告：<target skill>（<smoke/full>，<YYYY-MM-DD>）
测试工作目录：<绝对路径>

### 1. 阶段矩阵
| 阶段 | 状态 | 检查项（通过/总数） | 问题摘要 |
|------|------|-------------------|---------|
| A 种子期 | ✅/❌/⚠️ | 16/16 | — |
| … | | | |

### 2. 问题清单（按严重度：❌ 失败 → ⚠️ 警告）
#### ❌ P1：<症状一句话>
- 位置：<阶段/文件/协议条款>
- 违反条款：<target 检查项/质量门编号——定位不到写"协议缺口：缺 XXX 条款">
- 证据：<产物路径/检查输出/样片摘要引用>
- 修复建议：<具体改动方向>
- 状态：待修复 / 已修复（重跑验证后）

#### ⚠️ P2：…
（P1=阻断发布；P2=应修复；P3=建议——质量门红牌升 P1）

### 3. 机械扫描结果
<03-checks.md §四 的输出>

### 4. 返修路径验证
[改:] 是否触发：目标阶段重跑 + before/after diff + director-log 记录（通过/失败）

### 5. 结论
- 可发布 / 需修复后发布（附 P1 列表）
- 协议缺口汇总（检查项本身含糊/缺失的地方——这些是 skill 文件要改的）

### 5.5 成品整体评判（与流程结论分离）
- **流程通过**：检查项全过 / n 项未过（协议层面）
- **成品成立**：整体有分量 / 整体平庸 / 垃圾（作品层面——测试产出的故事/剧本作为作品值不值得存在）
- **落差诊断**：若流程全过但成品平庸——哪条检查只查了"存在"没查"分量"？（这是检查体系盲区，P1 级信号喂 skill-evolution）
- 案例登记：《第十七道痕》（2026-08-02 full）——流程全过 / 成品垃圾 / 落差：执有来路无重量、节气到位事件轻、失候0节奏平
```

## 二、严重度映射

| 级别 | 判定 | 处置 |
|------|------|------|
| P1 | 流程跑不通/质量门红牌/引用断链/协议字段缺失 | 阻断发布，必修 |
| P2 | 检查未过但可绕行/警告级疑点 | 应修复 |
| P3 | 建议（火候/可优化） | 可选 |
| 协议缺口 | 检查项本身含糊无法判定/Procedure 缺步骤 | 记入"skill 文件待改"清单（P1 级处理——协议缺陷） |

## 三、与 skill-evolution 的接口

E2E 报告 = **测试信号**，按以下方式输入 skill-evolution：

```
1. 报告问题清单 → skill-evolution 信号扫描的"测试发现"类信号
   （每条：位置/违反条款/证据——与 skill-evolution 提案格式兼容）
2. skill-evolution 出优化提案（AI 提议、用户裁决）→ 应用修复
3. 修复后重跑本 E2E（对照问题清单逐条验证 → resolved/unresolved）
4. 闭环后报告更新：修复记录 + 重跑结果
```

触发方式：E2E 完成后提示"报告已就绪——是否交给 skill-evolution 出修复提案？"（选择框：出提案 / 仅存档 / 完成）。

## 四、报告纪律

1. 每条问题必须能定位到条款（检查项编号/质量门编号/协议小节）——定位不到 = 记为协议缺口
2. 阶段矩阵的状态必须与问题清单一致（矩阵 ✅ 的问题不得出现在清单里）
3. 结论明确"可发布/需修复"——不写"基本没问题"
4. 测试日志（模拟导演回答、执行过程）单独存文件，报告只放结论与证据
