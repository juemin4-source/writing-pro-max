# 02 — 执行协议（AI 双角色 / 逐阶段执行与验收）

> 本文件是 SKILL.md「流程② 流程执行」的操作细则，不独立成立。

## 一、AI 双角色

| 角色 | 职责 | 什么时候切换 |
|------|------|-------------|
| 测试执行者 | 按 target SKILL.md 的 Procedure 执行每个阶段；出示样片摘要；验收 | 主角色 |
| 模拟导演 | **刻薄、挑剔、高要求**（画像见 01-test-cases.md）：按脚本回答决策点、拒绝第一稿、连环 `[改:]`、质疑判断依据、抓自相矛盾；签核 | 导演决策点时切换 |

规则：
- 两个角色**分层记录**：执行者的行为写入 E2E 日志；模拟导演的回答标注「模拟」——报告里区分"协议行为"与"内容质量"
- 模拟导演的 `[改:]` 必须真实触发返修流程（重跑目标阶段 + before/after diff），验证返修协议本身；连环返修验证 2 轮上限与终裁路径
- 选择框交互用真实 AskUserQuestion（测交互协议）——模拟导演即测试者本人选脚本选项
- **压力测试原则**：模拟导演不迁就 AI——AI 应对得当则继续，应对失当（不交代依据/不响应批注/编造理论）即记录为 FAIL（协议未扛住高要求用户）

## 二、逐阶段执行与验收

每阶段四步：

```
1. 执行：按 target SKILL.md 的阶段操作步骤产出
2. 出示样片摘要（协议要求）→ 模拟导演裁决（脚本）
3. 验收：对照该阶段可判定检查（target frameworks 末尾清单）+ 相关质量门
4. 记录：✅ 通过 / ❌ 失败 / ⚠️ 警告 + 证据（产物路径/检查输出/样片摘要引用）
```

验收判定：
- ✅ 通过：检查项全过，证据充分
- ❌ 失败：有检查项未过（记录违反的条款 + 证据）
- ⚠️ 警告：通过但发现协议疑点（如检查项本身含糊无法判定——这本身就是 E2E 要抓的"协议缺口"）

## 二.5、允许涌现（创作中途生长的执行规则）

> 导演画像 ⑪：大纲落地前涌现出的更好情节 = 机会不是错误（对应《人物篇》"位置会挪移"——人物会在故事里试着挣脱初始命运）。

- 执行中若出现比既定大纲更好的情节走向（模拟导演或执行者提出）：**接受并改大纲**，记录为「涌现点」（位置 + 替代方案 + 为什么更好）
- 涌现点不是协议失败：**验证的是"流程能否容纳中途生长"**——流程拒绝生长（卡死在大纲上）= FAIL；流程接受生长并正确联动下游（时位/节气/人物随之调整）= PASS
- 涌现点记录格式：`涌现点：<阶段> 原定 <X> → 涌现 <Y>（依据：<为什么更好>）→ 大纲修订 + 下游联动 <哪些检查重跑>`
- 与 ② 连环返修的区别：返修是"改错"，涌现是"改好"——报告分开记录

## 三、smoke 模式的抽样规则

- 种子期（A）必须完整跑（交互协议最密集，bug 高发区）
- 后续阶段各抽样 1-2 个验收点（每个质量门大类至少覆盖 1 条）
- 机械扫描全量跑（smoke 不减机械检查）
- 报告标注"smoke 未覆盖的阶段"

## 三.5、整体性评判（防"流程通过、成品垃圾"）

> E2E 实测教训（2026-08-02）：《第十七道痕》全部检查通过但成品平庸——检查项只查"有没有"，不查"够不够好"。E2E 必须区分两个结论。

每阶段验收追加"**整体性一瞥**"：这个产物到现在为止，作为一个整体还有没有魅力？哪个位置开始失去牵引？——记录为阶段矩阵的附加列（✅ 仍成立 / ⚠️ 开始失魅 / ❌ 已无魅力）。

报告结论**必须区分**：
- **流程通过**（检查项全过）——协议层面
- **成品成立**（整体有分量）——作品层面

两者可以分离：流程全过 + 成品垃圾 = 报告照实写（这正是检查体系盲区的信号，喂给 skill-evolution）。

## 四、执行纪律

1. 严格按 target SKILL.md 的 Procedure 执行——E2E 测的就是 Procedure 本身可不可跑；Procedure 说"问输出位置"就必须弹框（弹不出来 = 协议失败）
2. 不替 target skill 补漏：协议缺步骤时记录"协议缺口"，不自行补跑
3. 超时/卡住的阶段：记录卡住点（哪个指令后无响应）——"卡住"本身是 E2E 最有价值的发现
4. 每阶段产物落测试工作目录（不落 target skill 目录）
