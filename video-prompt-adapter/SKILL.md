# Video Prompt Adapter — 表演驱动的视频提示词

## Core Thesis

A great video prompt is a director's performance note: it tells the model **what to play, how to play it, and what not to play** — performance-driven, not scene description.

> 好的视频提示词是导演的表演指令：告诉模型**演什么、怎么演、不演什么**——表演驱动，不是画面描述。

画面描述只能生成"正确的空壳"；表演驱动才能生成"活的人"。用户实战标准（2026-08-01 三批黄金样本）证明：表演层（角色内在 → 内心变化轨迹 → 微表演指令 → 否定约束）是提示词质量的分水岭，官方 Seedance 2.5 手册的表演核心行与情感解析层正是同一方向的官方雏形——07 的职责就是用系统化方法论补全官方缺口。

## Archetype

Primary: **Knowledge + Direction** — 表演导演知识 + 平台领域知识
Secondary: **Delivery** — 产出可直接粘贴到平台的提示词

## 三层结构总览

| 层 | 职责 | 载体 |
|----|------|------|
| **L1 表演层** | 角色内在、表演心理学、微表演词汇、否定约束、风格体系、镜头-关系 | `frameworks/performance-direction.md` + `frameworks/negative-constraints.md` |
| **L2 平台能力层** | Seedance 2.5 公式体系、@引用、时间戳控制、参数、12 条质量门 | `frameworks/seedance-official-format.md` + `frameworks/prompt-adapters/seedance-2.5.md` |
| **L3 管线接口** | 输入承接（06/剧本/角色卡/continuity-locks）、04 知识库引用、导演模式 | `frameworks/prompt-adapters/asset-reference.md` + 本文件「管线接口」章 |

三层缺一不可：只有 L1 不落地（平台不认），只有 L2 是死格式（没戏可演），只有 L3 是空壳（没内容）。

## L1 表演层（核心）

每个含人物的视频提示词**必须包含表演层**，六件套：

### 1. 角色内在（人设段）
- **性格气质**：一句话定性（写法模板见 performance-direction.md §1，如"沉稳、寡言、有分寸感"式组合）
- **表演基调**：情绪表达的尺度（"细腻、不夸张、不外放、不做表情包式演法"）
- **一致性锚点**：脸型、五官比例、年龄感、发型结构、整体气质——逐项列出，防换脸/防漂移

### 2. 表演心理学（过程感与潜台词）
- 内心变化的**轨迹**：日常/礼貌态 → 触发点（一句话/一个消息/一个人）→ 轻微但明确的变化
- 情绪的**心理实质**：写"是什么、不是什么"（不是甜美摆拍，而是细的羞意和不知所措）
- **时间窗口**：精确到"刚发生的那几秒"

### 3. 微表演指令（词汇库见 performance-direction.md §3）
眼神、面部、呼吸、手部、身体、节拍、声音七类，指令级可执行，如：眼神停顿、视线偏移、嘴角变化、下颌收紧、呼吸变化、手部小动作、动作中段、"看了三秒，表情从 X 到 Y"。

### 4. 否定约束层（见 negative-constraints.md）
- 一致性否定：不要换脸、不要漂移、不要网红脸/AI 美女
- 质感否定：不要影楼感、不要写真感、不要过度精致、不要强 AI 感
- 表演否定：不要夸张哭喊、不要直给情绪、不要表情包式演法
- 场景否定：不要样板间（要生活痕迹和有序的乱）

### 5. 风格体系参数化（B5）
统一调色写成可替换的参数块：**高光色 + 阴影色 + 饱和度 + 反差 + 胶片质感**。内置体系模板（现实暖黄橙 / 科幻冷灰蓝白+唯一高饱和色 / 赛博霓虹 / 水墨……），并引用 04 五行色彩（水基调 = neon-fluid 等）。

### 6. 镜头-关系逻辑（B6）
机位为关系服务，不只为构图服务：过肩（权力/连接）、仰视（压迫/神性）、固定（克制/旁观）、主观视角（代入）。"中近景，带一点画外对手的肩膀或背影，让关系成立"。

**表演层组装模板与写法细则 → `frameworks/performance-direction.md`**

## L2 平台能力层（Seedance 2.5）

### 平台规格表（2.5 参数，权威源 = 官方手册）

| 规格 | Seedance 2.5 |
|------|-------------|
| 单次生成时长 | 4–30 秒（97–721 帧）；duration 可选 -1 |
| 视频延长 | 底片 ≤30s，单次延长 4–30s，套娃累计最长 **60s**；必填延长动词 |
| 超长视频模式 | 一次性 **30–180s**（全局参数置顶 + 素材@清楚 + 故事描述清楚） |
| 分辨率 | 480p / 720p（网页端 720P+） |
| 画幅 | 16:9 / 9:16 / 1:1 等 |
| 图片参考 | ≤ 30 张（单张 <30MB，含 heic/heif；请求体 <64MB，大文件勿用 Base64） |
| 视频参考 | ≤ 10 段（单段 2–30s，总时长 ≤30s） |
| 音频参考 | ≤ 10 段（总时长 ≤30s）；支持仅音频输入 |
| 平台模式 | 全能参考 / 智能编辑 / 超长视频 / 首尾帧 |
| 稳定性阈值 | 主体 1–5 个效果好（6–10 可尝试）；主体时长 5–10s 好；主体图 1–8 好（9–12 可尝试）；编辑输入 ≤20s 好 |
| 小语种 | 中英西印马重点优化 + 泰阿葡越日韩覆盖 |
| 语言 | 全部提示词用中文（或目标语种）编写 |

### @ 引用系统（每个引用必须标明用途）

```text
@图片1（人物[面孔/特征]一致性）  @图片2（构图/白模/空间关系）  @图片3（场景）
@视频1（运镜）  @视频2（动作）  @音频1（BGM）  @音频2（音色参考，挂台词后）
@参考图1-@参考图5（范围引用）     素材编号 = 上传顺序，图/视频/音频各自独立
```

### 时间戳文本控制（2.5 核心新特性）

- 语法：秒段式 `0s-3s：…` / 时间码式 `[00:00 - 00:07]` / 帧数式 `第 0–90 帧 (0s - 3s)`——**帧数+秒数双写最稳**（24fps 验证准确）
- 每段时间切片四层：`[起-止秒数]+[核心阶段/主题]` → `[动作/表情物理指令]` → `[情感解析/镜头调度潜台词]` → `[其他要求]`
- **潜台词层不可省**——纯物理指令会被机械执行（官方原话精神）

### 公式体系（八套，详见 seedance-official-format.md）

基础公式 / 30 秒长视频三层公式（含表演核心行）/ 超长视频公式 / 真人人物 7 维公式 / 编辑四要素公式 / 转场三段式 / 白模两粒度公式 / 多宫格分镜公式。

### 时长策略（2.5）

| 时长 | 策略 |
|------|------|
| 4–8s | 聚焦 1–2 个画面，表演给一个完整动作节拍 |
| 9–15s | 时间戳分镜 2–4 段，每段含潜台词 |
| 15–30s | 时间戳分镜 4–6 段（单次上限 30s） |
| 30–60s | 视频延长拼接：衔接点 = 上段结尾状态 = 下段开始状态 |
| 60–180s | 超长视频模式：全局参数 + 素材@清楚 + 故事描述清楚 |

### 禁止项与静音

- 禁止项四维：**声音 + 字幕 + 行为 + 崩坏高发处**（五官/肢体/穿模/物理逻辑）
- **静音逐项写**：无 BGM / 静音生成 / 无旁白 / 无环境杂音——不笼统写"不要声音"
- 版权规避显式写（"规避《变形金刚》等已知版权 IP 元素"）；儿童内容禁 IP/logo/商标/水印

### 导演模式（简化版，参照 02 frameworks/13 精神）

产出后**立即出示样片摘要并声明完成状态**，然后停下来等导演指令——不自动前进。

```
07 产出 → 出示样片摘要 → 声明状态 → 等导演：[通过 | 改:... | 自检 | 评审]
```

**样片摘要**（每次产出必附）：

```text
## 样片摘要
- 覆盖：EP04-S05 共 N 个镜头（shotId 列表）
- 表演层：每镜头的表演核心/微表演指令摘要
- 风格体系：选用的调色模板与光位
- 质量门：12 条机械检查结果（全过 / N 条未过清单）
- 关切：导演需注意的点（如有）
```

**完成状态协议**（四选一，状态缺失 = 阶段未收尾）：

| 状态 | 含义 |
|------|------|
| `DONE` | 产出完整，12 条机械检查全过，无导演关切 |
| `DONE_WITH_CONCERNS` | 产出完整但有机械检查未过项或判断性关切（须列出） |
| `BLOCKED` | 输入缺失/矛盾（如 shot-package 无 performance 字段、continuity-locks 断链），说明缺什么、要谁补 |
| `NEEDS_CONTEXT` | 缺导演意图（题材/情绪基调/风格选择未定），返回澄清 |

**导演指令**：

| 指令 | 07 动作 |
|------|---------|
| `[通过]` | 收尾，记 director-log（decision=pass） |
| `[改:...]` | 按批注返修，改前快照，记 director-log（decision=revise，rationale 必填） |
| `[自检]` | 重跑 12 条机械规则 + 表演层检查清单，报告差异 |
| `[评审 <目标>]` | 转 08 评审团 |

**指令呈现（AskUserQuestion 选择框）**：出示样片摘要后，必须调用 AskUserQuestion 弹出导演选项，不裸等文本输入——借鉴 gstack 的 AskUserQuestion 交互（Main Design 2026-08-01：「样片摘要模板…借鉴 gstack AskUserQuestion」）。

```
question: 07 样片摘要已出示，导演指令？
header:   导演指令
选项（≤4 个，推荐项放第一位并标注「（推荐）」）：
  [通过]        —— description: 收尾，记 director-log（decision=pass）
  [改:<批注>]   —— description: 按批注返修（改前快照）；批注请选 Other 输入
  [自检]        —— description: 重跑 12 条机械规则 + 表演层检查清单，报告差异
  [评审 <目标>] —— description: 转 08 评审团；目标请选 Other 输入
```

- 需要自由文本的指令（改:/评审 目标）由用户选 Other 输入，按指令语法解析
- decision 映射：通过→pass / 改→revise / 自检→self_check / 评审→council
- rationale 必填：取用户注解（AskUserQuestion 注解栏）；无注解时记「导演选择 <选项>」（理由缺失 = 裁决未完成）
- 回退：非交互环境退回文本等待，指令语法不变

**裁决日志** `director-log.jsonl`（追加写，不覆盖）：

```json
{"ts":"2026-08-01T10:30:00+08:00","decision":"revise","target":"EP04-S05-SHOT-012","rationale":"表演核心缺潜台词层","detail":"重写该镜头情感解析"}
```

- decision 枚举：`pass | revise | revert | self_check | council | confirm_warn | accept | cut`
- rationale 必填（理由缺失 = 裁决未完成）
- 跨会话加载最近 5 条 → 导演偏好数据源

**输出位置协议（Output Location Contract）**：提示词文本/落盘产物**不写入本 skill 目录**（skill 目录只存定义文件）。产出前用 AskUserQuestion 问输出位置（提示词若只粘贴平台不落盘，声明"无落盘"即可）：

```
question: 产出输出到哪里？
header:   输出位置
选项（≤4 个）：
  [默认工作区]（推荐）—— description: State/Foundry/tasks/<项目名>-<YYYYMMDD>/（沿用 Foundry 任务目录惯例）
  [当前目录]           —— description: 写在当前会话工作目录
  [自定义路径]         —— description: 选 Other 输入完整路径
```

- 默认工作区路径规则：`State/Foundry/tasks/<项目名>-<YYYYMMDD>/`；项目名未定用 `video-prompt-adapter`；日期用开工日
- 回退：无交互环境默认「默认工作区」

## 质量门：12 条可判定规则

每条规则标注判定方：`[机械]` = 可进机械检查（文本谓词）；`[导演]` = 判断性，必须导演判定。判定方为"机械+导演"的，机械查结构、导演判质量。

| # | 规则 | 判定方 | 检查点 |
|---|------|--------|--------|
| 1 | @引用完整性 | [机械] | 每个 @ 引用紧跟用途标注；素材描述按上传顺序编号 |
| 2 | 时间戳覆盖律 | [机械] | 闭区间（起-止秒）、按时间顺序、首段 0s 起、末段覆盖全时长、段间连续无跳段 |
| 3 | 时长档位律 | [机械] | >30s 必须走超长视频模式；延长仅对 ≤30s 产物、单次 4–30s、累计 ≤60s |
| 4 | 延长必填词 | [机械] | 含"向前/向后延长、延续、续写"类动词 + 仅描述新增时段画面 |
| 5 | 转场三段式 | [机械] | 齐 [转场类型指引]+[基础约束]+[切镜逻辑]，含"禁止生硬切镜、禁止物体凭空出现" |
| 6 | 真人公式覆盖 | [机械]+[导演] | 7 维至少 4–5 维（含"保留真实毛孔纹理"保真后缀、面部特征 ≥3 点）；"人物设定完整"终判导演 |
| 7 | 禁止项四维 | [机械] | 声音+字幕维度（无字幕/无BGM）+行为+崩坏高发处（五官/肢体/穿模/物理逻辑）各 ≥1 项 |
| 8 | 编辑四要素 | [机械] | [标注工具与方位]+[修改对象]+[变化描述]+[生效时序] |
| 9 | 白模映射律 | [机械] | 粗颗粒须有对应关系映射；细颗粒以"将[视频1]的白模动画渲染成最终成片"开头 |
| 10 | 无缝转场三要素 | [机械] | 声明不修改原视频 + 衔接元素延续描述 + 约束形状/位置/大小/运动方向一致 |
| 11 | 30 秒结构律 | [机械]+[导演] | 总述 + 全局设定（含表演核心与禁止项）+ 时间戳分镜（含潜台词）三层齐全；潜台词质量导演判 |
| 12 | 静音约束 | [机械] | 逐项写（无BGM/静音生成/无旁白/无环境杂音），不笼统"不要声音" |

### 表演层检查清单（[导演] 判定）

机械检查之外，表演层还有四条判断性门，逐条问导演或在样片摘要中自评：

1. **心理学轨迹成立**：日常态 → 触发点 → 内心变化，三点齐且有因果？（不齐 = 表演没戏）
2. **潜台词解释了物理指令**：每个微表演动作都写清了"为什么这么演"？（纯物理指令 = 机械执行风险）
3. **微表演可执行**：指令都是可拍摄的可见细节，没有"心情复杂"这类不可拍词
4. **否定约束与题材匹配**：防的是本题材的真 AI 通病（现实人防换脸/影楼感，机甲防软体穿模，儿童防 IP）

## Procedure

```
1. 读输入：06 shot-packages / 剧本场景 / 角色卡 / continuity-locks（缺 → BLOCKED/NEEDS_CONTEXT）
2. 定题材与时长档位（4-8 / 9-15 / 15-30 / 延长 / 超长）
3. 表演层起草：每镜头按 performance-direction.md 六件套写
4. 否定约束：按 negative-constraints.md 题材清单选配
5. 平台层组装：按 seedance-official-format.md 公式 + 时间戳 + @引用 + 禁止项
6. 风格体系：调色参数块 + 04 引用（五行/光位/焦段）
7. 跑 12 条机械检查（质量门），标出未过项
8. 结构化为 schemas/seedance-prompt.schema.json，运行 scripts/assemble-prompt.js 组装
9. 出示样片摘要 + 声明状态 → 等导演 [通过|改:|自检|评审]
10. 每次返修：快照 → 改 → 重跑机械检查 → 记 director-log.jsonl
```

## Troubleshooting

| 问题 | 原因 | 解决 |
|------|------|------|
| 人物像木头站着 | 只有画面描述，没有表演层 | 补表演核心行 + 微表演指令 + 潜台词 |
| 情绪直给、表情包演法 | 缺表演基调与否定约束 | 人设段写"克制、不夸张"，否定层加"不要直给情绪" |
| 表演做完了但不像在演戏 | 缺内心变化轨迹 | 补心理学段：日常态 → 触发点 → 变化 |
| 脸漂移/换脸 | 一致性锚点缺失或未 @ 人物图 | 人设段列锚点 + `@图片1 的人物[面孔/特征]一致性` + "不要换脸" |
| 镜头没有叙事意义 | 缺镜头-关系逻辑 | 机位为关系服务：过肩=权力，仰视=压迫，固定=克制 |
| 多镜头剧情快进 | 时间戳缺失 | 时间戳分镜 + 每段四层（含潜台词） |
| 时长超限报错 | 档位错 | 检查时长档位律（>30s 走超长模式；延长累计 ≤60s） |
| 随机字幕/BGM 出现 | 禁止项笼统 | 逐项写：无字幕、无BGM、无旁白、无环境杂音 |
| 多人同框像双胞胎 | 未锁各自特征 | 每人独立锚定 + "不串脸、不换装、特征互不干扰" |
| 生成失败 | 素材格式/大小 | 图片 <30MB、视频单段 ≤30s 总 ≤30s、请求体 <64MB |
| 2.5 偶发物理瑕疵 | 模型边界 | 记入 director-log 的 acceptable_limitation，不反复重抽 |
