# Novel Original Writing — 原创剧本流协议

> **中文唤起**：直接说「用原创剧本流…」「概念到剧本…」「从零写剧本…」即触发本 skill（英文名 novel-original-writing 仅为目录/命令标识，日常一律用中文）。

## Core Thesis

Foundry 电影管线的**原创入口**，与 02 改编流（novel-to-screen-adaptation）并行：概念直接到剧本，不经过小说。

> 改编流保留原句背后的叙事功能，更换信息载体；原创流从概念长成叙事功能本身——没有保真锚点，只有概念一致性。

与改编流的差异：

| 维度 | 02 改编流 | 本协议（原创流） |
|------|----------|----------------|
| 输入 | 小说文本 | 概念/命题/题材（无文本） |
| 锚点 | 源文本保真 | 概念一致性（每个产物可回溯到概念） |
| 内心外化 | 转译（小说→屏幕） | 发生在创作源头（人物生成时即外化） |
| 选题 | 无 | 含选题引导（A 种子期） |

**本协议不产出"好点子大纲"。本协议产出"可以拍、演得出、留得下余震的剧本"。**

---

## 输入与格式路由

输入：概念 / 命题 / 题材（一句话起步，可多句话）。先做格式路由（体量判断），再进七阶段：

| 体量 | 适用 | 产出规模 |
|------|------|---------|
| 短剧 | 竖屏短剧/每集 1-3min | 概念→世界→人物→结构→至少 2 场完整剧本 |
| 单集 | 单集电影/短片 | 完整七阶段 → 单集剧本 |
| 长片 | 院线/网大 | 完整七阶段 → 全片场幕表 + 关键场剧本 |
| 系列 | 剧集/多季 | 全书周期 + 分卷周期 → 首集完整剧本 + 后续大纲 |

---

## 七阶段结构（A 种子 → G 余震）

```
输入: 概念/命题/题材（无文本）→ 格式路由（体量：短剧/单集/长片/系列）
  ↓
A 种子期   概念组合（@山音 STC）→ 五秒可理解检验 → 悬念五类 → 叙事入口（三依据·六切口）
  ↓
B 世界生成期  麻雀世界观：硬规则 6 + 历史压力 5 + 世界推导七步
  ↓
C 人物生成期  八步操作法 → 五层生成验证（私9/处9/执7/为7/已6）→ 能力（万用矩阵/扑街十问）
  ↓
D 结构期    命运大纲十二问 → 叙事大纲（情绪承诺/主体七选/截取/首尾/信息分配/主要问题）→ 时位细纲
  ↓
E 载体翻译期  章纲七要素 → 场/幕结构 → 场景卡 9 字段（引用 02 模板）→ 节拍表 → 剧本硬规则
  ↓
F 表演层注入  角色内在/表演心理学/微表演指令/否定约束（引用 07 文件）
  ↓
G 余震期    大雪（余震留雪下）/ 冬至（种子够小，不开新坑）+ 归藏检验（新常态入日常/关系结霜/未耗尽问题）
  ↓
03-09 生产链照接（拆解→生图→分镜→视频提示词）
```

### A 种子期（《故事天演论》前提 × 命运篇入口判定）

**目的**：让一个想法变成"别人愿意继续追问的局面"——**入口很低、经验很高**（门要开得清楚，但门后必须有世界），并决定读者第一脚踩在哪。操作细则见 `frameworks/00-seed.md`。

**交互模式（默认：引导式追问，不一口气编前提）**：

> 种子期是**和用户一起根据理论追问出前提**，不是 AI 把前提编出来。材料（愿望/欲望/变化/追问/暗动）必须由用户给出；AI 只做三件事：**① 出示理论工具与问题 ② 整理用户已提供的材料 ③ 用理论校验与反问**。用户没答的题，AI 不发明答案——宁可停在这一轮继续追问。逐轮确认后写入 checkpoint。
>
> 例外：用户显式要求"你帮我编/直接生成"才进入代写模式——代写产物必须逐条标注材料来源（哪条来自用户、哪条是 AI 补的），并回传用户逐项确认。

**追问节奏（13 轮，每轮等用户回答再进下一步）**：

| 轮 | 理论工具 | 问用户什么（AI 不编） | AI 做什么 |
|----|---------|---------------------|----------|
| 1 | 作者愿望清单 | 最近反复想写什么？先列原矿（不要求像故事） | 分类标注（欲望/材料/深处问题），问"哪条最发热" |
| 2 | 欲望八象（内） | 这个材料里，人物可能有什么欲望？ | 用八象对照帮用户辨认，由用户确认 |
| 3 | 六变一常（外） | 世界可以发生哪种变化？逐项过 | 指出每种选择的类型气质（荒诞/职场/温情…） |
| 4 | 内外相交 | （组合用户材料）前提句草案 | 只组合用户已答材料成句，交用户改 |
| 5 | 三个剧情追问 | 读者会自然问哪三个问题？ | 校验追问是否推动故事、答案是否在局中 |
| 6 | 低入口高经验验收 | 前提句里读者能看清四件事吗？ | 失真检查逐条问（胜利有后果吗/圆满处理伤害吗…） |
| 7 | 私生人物检验 | 这个前提能长出几种不同"私"的人？ | 给 1 个示范（用用户材料），引导再想 1-2 个 |
| 8 | 类型与场域 | 这个世界在哪发生？哪些规则挡人？ | 校验规则 ≥3 条且阻挡欲望（接 B 阶段） |
| 9 | 欲望分层 + 生长法 | 入口欲望通向哪层经验？追问往哪边长？ | 对照 8 经典路径；确认生长主路（接 D 结构期） |
| 10 | 值得写 gate | 为什么非写它不可？给读者什么承诺？ | 三问逐问；"多出的一刀"；缺憾连时代追问 |
| 11 | 尺度路由 | 这个故事多大？ | 对照尺度表定格式路由 |
| 12 | 叙事入口 | 读者第一脚踩在哪？ | 三依据六切口对照 |
| 13 | 冬至暗动 | 显出来以前，旧局里什么已经在暗处动？ | 校验"雪下有动"可指认 |

**操作步骤（= 追问轮次，逐轮执行）**：
1. 轮 1 愿望清单 → 2. 轮 2 八象 → 3. 轮 3 六变一常 → 4. 轮 4 前提句草案（只组合用户材料）→ 5. 轮 5 三个追问 → 6. 轮 6 低入口验收 → 7. 轮 7 私生人物 → 8. 轮 8 场域 → 9. 轮 9 欲望分层/生长主路 → 10. 轮 10 值得写 → 11. 轮 11 尺度 → 12. 轮 12 入口 → 13. 轮 13 暗动

**输入**：概念/命题/题材 + 导演的格式路由确认（或只有"我想写点什么"——从轮 1 开始）
**输出**：`checkpoints/00-seed.md`（前提句 + 八象/六变一常 + 低入口验收 + 场域 + 生长主路 + 值得写三问 + 入口判定 + 暗动；每项标注"用户提供/AI 整理/用户确认"）

### B 世界生成期（命运篇·麻雀世界观）

**目的**：把概念落成一个有缺憾、有历史、有日常的世界——世界缺什么，人物就在哪受压。

**操作步骤**：
1. **硬规则 6**（人物篇第一章"先写一个麻雀世界观"）：
   ① 核心异常：这个世界最不正常的一件事是什么？（一句话）
   ② 机制追问：它靠什么运转？奖励什么、惩罚什么、默认什么？
   ③ 美学辨识度：颜色、气味、材质、光线、时代感——世界在观众眼里一眼可认
   ④ 世界缺憾：世界缺什么？（主角缺憾必须与世界缺憾关联）
   ⑤ 规则代价与执行人 4 问：规则由谁定、谁执行、谁承担代价、谁可以豁免？
   ⑥ 当前局势：为什么故事现在发生？+ 真相与悬念：世界隐藏了什么
2. **历史压力 5**（命运篇/人物篇）：
   ① 势力：主要势力各自的目的/资源/依靠/彼此冲突
   ② 货币与供养：最稀缺的东西是什么、谁分配它、谁被延后
   ③ 阶级身份名分资格：谁有资格说话、谁只能沉默
   ④ 信仰与禁忌：什么被相信、什么被禁止
   ⑤ 日常一天：一个普通人怎么过一天（世界从概念变生活）
3. **世界推导七步**（缺憾→人）：缺憾 → 谁被伤害 → 谁维护 → 谁知道历史 → 谁靠漏洞活 → 谁承受日常 → 主角如何解决
4. **主角缺憾-世界缺憾关联确认**：世界缺什么，主角就在哪受压；主角的解决路径必须对着世界缺憾打

**输入**：00-seed.md（logline 中的世界设定）
**输出**：`checkpoints/01-world.md`（硬规则 6 + 历史压力 5 + 推导七步结论）

### C 人物生成期（人物篇）

**目的**：从世界机制的受力点里长出人物，再用五组问题清单把人物验证到"能说话、会沉默、有来路"。

**操作步骤**：
1. **八步操作法**（人物篇第二章"八、实际操作"）：
   ① 一句话故事机制（真正让人卷进去的核心机制）
   ② 八受力位置（承受/控制/排除·失落/代价/维护/知情/象征/显影——每个位置落谁）
   ③ 定主角（不是最惨的人，是最能把问题推下去的人）
   ④ 配第一圈人物：三助一压——同路者/带路者/支撑者/直接压力者
   ⑤ 判断孰敌孰友（机制位置 ≠ 阵营）
   ⑥ 点连成网（九问：彼此认识吗/谁欠谁/谁怕谁/谁保护谁/谁误会谁/谁曾是同伴/谁现在站不同边/谁的死亡会改变另一人位置/谁的选择会牵出下一批人）
   ⑦ 长篇递归（总机制→篇章机制→地区机制→组织机制→个人机制）
   ⑧ 合并、升格、删除（功能重复的合并；一人多位值得升格；不改变选择与压力的删）
2. **五层生成 + 验证**（人物篇第三至七章）：对每个重要角色依次填写五组问题清单（38 问，见 frameworks/02-character.md 完整表单）：
   - 私九问（资取/边界/好恶/所喻）→ 处九问（天/地/人处境）→ 执七问（旧答案/奖励/羞耻/四形态/显形者/改变成本）→ 为七问（所求/压力/计划/能力/命名/外在/涟漪）→ 已六问（六方向+完成未竟+显露结算+起点回响）
3. **执四形态确认**（正/偏/旧/邪）+ 执的阶段变化记录（正执可失度成偏执，旧执可被修正，偏执可因羞耻和利益变成邪执）
4. **能力设计**（番外"能力"）：万用矩阵映射（八欲望生/逸/乐/和/权/变/名/道 × 正/反/合）+ 扑街十问诊断（详见 frameworks/02-character.md）
5. **能力与执互验**：能力放大人物的执，而不是替人物逃课

**输入**：01-world.md（机制 + 受力点）
**输出**：`checkpoints/02-characters.md`（每人一份五组问题表单 + 能力矩阵 + 关系网图）

### D 结构期（命运篇·时位）

**目的**：把人物命运排进十二节点和二十四节气——知道每件事处在什么时位，该藏还是该露。

**操作步骤**：
1. **命运大纲十二问**（命运篇第三章"十二节点"）：藏（问题藏在哪）/ 生（新势从哪冒）/ 将动（裂缝如何逼近）/ 动（事情如何发动）/ 长（什么开始增长）/ 将育（增长如何组局）/ 育（局面如何育成）/ 止（盛极处什么反力）/ 将杀（旧答案如何进入清算）/ 杀（哪条旧路被杀）/ 归（意义如何归位）/ 将藏（结果如何沉入下一轮）
2. **叙事大纲**（命运篇第三章末尾）：情绪承诺（承诺什么情绪）/ 叙事主体七选（主角/群像/案件/组织/时代/世界/认知）/ 截取范围（从命运的哪里开始到哪里结束）/ 开头结尾（怎么进、怎么收）/ 信息分配七种（顺叙/插叙倒叙/多视角/误解/读者多知/人物多知/不给完整答案——七选一 + 一致执行）/ 主要问题（观众追什么问题）
3. **时位细纲**：主角线 / 盟友线 / 反派线 各排节点；支线在"将"位接入（将动推主线发动 / 将育参与组局 / 将杀把代价送回主线 / 将藏把余波沉入下一轮），不占正节点
4. **二十四节气验收句逐条过**（24 条，见 frameworks/03-structure.md——每幕/每场可判）：写一段内容时问"这条线现在在什么节气"，对照验收句判断火候
5. **大中小周期对齐**（第四章）：全书周期是主景；卷/区域是中周期；人物/支线是小周期——主线入秋时支线不能还在春花，全书是春时支线不能霜降

**输入**：02-characters.md（人物命运线）
**输出**：`checkpoints/03-structure.md`（命运大纲 + 叙事大纲 + 时位细纲三线节点）

### E 载体翻译期（@山音 + 02）

**目的**：把结构翻译成可拍的场、幕、场景卡、节拍表和剧本正文。

**操作步骤**：
1. **章纲七要素**（命运篇"大纲写法·章纲"）：视点 / 发生什么事 / 人物动机 / 阻力 / 变化 / 释放或隐藏什么信息 / 钩子
2. **章纲 → 场/幕结构**：视点决定镜头主语；一章可拆多场，一场只完成一个功能；功能重复的场合并
3. **场景卡**（9 字段，引用 `novel-to-screen-adaptation/templates/scene-card.md`）：目标/阻碍/冲突/变化/信息揭示/关系变化/屏幕物件/内心外化/视觉策略 + 结束状态/可删
4. **节拍表**：每场先写节拍（BEAT 序列 + TURN 点）再写剧本
5. **剧本正文**（引用 `novel-to-screen-adaptation/templates/screenplay-scene.md`）按剧本硬规则（语义与 02 协议一致，不重复发明）：
   - 动作描述占比 ≥ 40%
   - 每段对白 ≤ 3 句（否则打断或压缩）
   - 无不可拍词（她感到/她意识到/她记得/她突然明白 → 死刑）
   - 对白必须有潜台词（不直接说意图）
   - 场景必须有转场；开场第一画面必须有视觉 hook

**输入**：03-structure.md（时位细纲）
**输出**：`checkpoints/04-scenes/`（场景卡）+ `checkpoints/05-beats/`（节拍表）+ `checkpoints/06-screenplay.md`（剧本正文）

### F 表演层注入（07）

**目的**：剧本人物直接带表演指令——角色内在、表演心理学、微表演指令、否定约束。

**操作步骤**（详细方法论引用 07 文件，不复制内容）：
1. **角色内在**（人设段）：性格气质一句话 + 表演基调（情绪表达的尺度）+ 一致性锚点（脸型/五官/年龄感/发型/气质逐项列出）
2. **表演心理学**：内心轨迹三段式（日常态→触发点→内心变化）+ 情绪实质（是什么、不是什么）+ 时间窗口（精确到几秒）+ 潜台词层
3. **微表演指令**：从 07 微表演词汇库选 3-6 个可见细节，按发生顺序排列（眼神/面部/呼吸/手部/身体/节拍/声音七类）
4. **否定约束**：按题材从 07 否定约束库选配（四维全覆盖：声音/字幕/行为/崩坏高发处）
5. **表演核心行**：每场关键人物写一行表演核心（基调词 + 3-6 个微表演清单 + 禁过度项）

**输入**：06-screenplay.md
**输出**：`checkpoints/07-performance.md`（每场的表演层段落，回填剧本）

### G 余震期（命运篇归藏 + 天演论余震）

**目的**：让结果归藏——余震留雪下，不是续集钩子；种子够小，不开新坑。

**操作步骤**：
1. **大雪 gate**（结尾验收）：喧闹真正落幕（不是所有情绪都要继续喊、不是所有伏笔都要当场拆开）；雪下留痕——暗处仍有新问题，但不必把故事重新打开；**余震来自前面所有不可逆变化**（人物不能回去、关系不能复原、旧答案失效、胜利带来新危险、失去进入日常），不是作者加一句深刻的话
2. **冬至 gate**（余味验收）：雪下的水声要小——小到像水泉在冰下动；动得太大 = 结尾变成新一轮开场，归藏被破坏；区分：余震 = 命运没有被彻底用完；钩子 = 强行开新坑
3. **归藏检验**（命运篇第九章）：新常态入日常（结果进入现实：规则/身份/关系/生活方式都变了）/ 关系结霜（谁还能站一起、谁不能回头、谁欠谁）/ 未耗尽问题（故事结束但某个问题在读者心里继续响）
4. **余震三问**（天演论）：故事结束后，读者仍然无法轻易完成判断吗？人物承受了观点之后留下复杂性吗？结尾留的是余震还是解释清楚？（"结尾要有余震，而不是解释清楚"）
5. **不可逆复核**：G 阶段不新增冲突解决，只检查"哪里回不去了"已经在 A-F 各阶段的产物里落实

**输入**：07-performance.md（定稿剧本）
**输出**：`checkpoints/08-ending.md`（大雪/冬至 gate 结果 + 归藏检验表 + 余震判定）

## 导演模式接入（简化版，07 风格，参照 02 frameworks/13 精神）

> 本协议由**导演驱动**：每阶段产出后暂停，出示一屏样片摘要并声明完成状态，收到导演指令后只重跑目标阶段及其下游（按 Files 表依赖级联），并出示 before/after diff。判断性决策由导演（用户）做出；机械检查（格式/字段/比例）保留自动。交互骨架（通过/改/自检三命令）借鉴 @山音 screenwriting-master（MIT），只借骨架。

### 1. 样片循环

```
每阶段产出 → 样片摘要（一屏）→ 声明完成状态 → 导演指令
   [通过] / [改:<自由文本批注>] / [自检] / [评审 <阶段或场景>]
→ 只重跑目标阶段及下游 → before/after diff → 再次出示样片
```

| 指令 | 含义 | 持久化产出 |
|------|------|-----------|
| `[通过]` | 签核本阶段产出，进入下一阶段 | director-log.jsonl 记 decision=pass |
| `[改:<批注>]` | 批注路由到目标阶段 + 具体修改（路由规则见下） | director-log.jsonl 记 decision=revise |
| `[自检]` | 对已产出物做机械检查（字段/比例/链路），不产审美结论 | 自检报告 + director-log.jsonl |
| `[评审 <目标>]` | 按需召集评审团（08-review-iteration 第三模式承接，透镜见下），导演当唯一法官 | 评审记录 + director-log.jsonl |

**批注路由**（简化确定性路由，不猜）：表演/不可拍 → E 或 F；节奏问题 → D 时位或 E 节拍；人物立不住 → C 五组问题清单；世界空洞 → B 硬规则；结局不响 → G 大雪/冬至 gate；概念分散 → A logline。路由置信度低时先回问澄清（"是时位还是动机？"）。

### 1a. 指令呈现协议（AskUserQuestion 选择框）

> 借鉴 gstack 的 AskUserQuestion 交互（设计文档：「样片摘要模板…借鉴 gstack AskUserQuestion」）：导演指令**用 Claude 自己的选择框弹出**，不裸等文本输入。

**出示样片摘要后，必须调用 AskUserQuestion 弹出导演选项**：

```
question: <阶段名> 样片已出示，导演指令？
header:   导演指令
选项（≤4 个，推荐项放第一位并标注「（推荐）」）：
  [通过]          —— description: 签核本阶段产出，进入下一阶段（如推荐通过则标注推荐）
  [改:<批注>]     —— description: 返修目标阶段及下游；批注请选 Other 输入（如「改:EP03 功能重复」）
  [自检]          —— description: 对产出做机械检查（字段/比例/链路），不产审美结论
  [评审 <目标>]   —— description: 召集评审团（透镜见「评审团透镜」）；目标请选 Other 输入（如「评审 C 人物生成期」）
```

- 四命令恰好放满 4 个选项上限；需要自由文本的指令（改:/评审 目标）由用户选 Other 输入，按指令语法解析（`[通过]` / `[改:<批注>]` / `[自检]` / `[评审 <目标>]`）
- **decision 映射**：通过→pass / 自检→self_check / 评审→council / 改→revise；自由文本按前缀解析
- **rationale 必填**：导演的理由取用户注解（AskUserQuestion 注解栏）；无注解时记「导演选择 <选项>，样片摘要推荐理由：<…>」——理由缺失 = 裁决未完成
- **回退**：非交互环境（无法弹出选择框）退回文本等待，导演以 `[通过]` 等指令语法输入，协议其余部分不变

**返修上限**：每阶段返修 ≤ 2 轮；超过后导演终裁于真实决策集：接受现状 / 召评审团换视角 / 删减元素缩小范围 / 终止该线。

### 2. 样片摘要模板（决策简报格式）

每阶段收尾前，把产出压缩为一屏决策简报：

```
## <阶段名> 样片
关键决策：<本阶段做的 1-3 个判断>
Gate 证据：<质量门机械检查结果 + 证据文件引用>
需要导演判定：<本阶段涉及 [导演] 标记的质量门编号>
推荐：<导演倾向的选项 + 一句理由>
选项与代价：<2-3 个选项 + 各自的人力/token 代价>
下一步：<AskUserQuestion 选择框已弹出> 通过 / 改: / 自检 / 评审
```

规则：Gate 证据必须引用具体证据文件（如 `checkpoints/03-structure.md`），不写空话；推荐是支点不是决定；[导演] 判定的质量门在样片摘要中逐条呈现。

### 3. 完成状态协议（四态）

每个阶段收尾必须声明且只声明一个状态；**状态缺失 = 阶段未收尾**，禁止「基本完成」「大概没问题」：

| 状态 | 含义 |
|------|------|
| `DONE` | 产出 + 签核完整 |
| `DONE_WITH_CONCERNS` | 完成但列出关切（导演可见） |
| `BLOCKED` | 第一阻塞点，附证据（文件+行/字段） |
| `NEEDS_CONTEXT` | 缺输入，说明缺什么（如"缺导演的概念方向"） |

### 4. 裁决日志（director-log.jsonl 协议）

每次导演裁决记录一条 jsonl，追加写不覆盖：

```jsonl
{"stage": "C 人物生成期", "decision": "revise", "rationale": "主角执七问第 3 问空答：羞耻没有载体，先补", "timestamp": "2026-08-01T10:23:00+08:00"}
```

- 字段：`{stage, decision, rationale, timestamp}`；decision ∈ `pass | revise | revert | self_check | council | confirm_warn | accept | cut | terminate`
- **rationale 必填——理由缺失 = 裁决未完成**
- timestamp 用 ISO 8601 本地时区
- 存储：`checkpoints/director-log.jsonl`；最近 5 条随样片摘要展示；跨会话自动加载（bootstrap 契约）。累积后即导演偏好数据源（味觉记忆最小版）

### 5. Session Bootstrap 契约

新会话开工自动加载：
1. 读 `checkpoints/director-log.jsonl` 最近 N 条 → 导演偏好
2. 按时间戳找最新 checkpoint 样片摘要/产物 → 上次干到哪
3. 检查各阶段完成状态声明（四态）→ 待决清单
4. 输出状态行："管线在 <阶段>，等导演 <指令>"；或"无可恢复上下文，从 A 种子期开始"

等待中的管线不自动前进；任何时刻可查询"我们在哪"。

## Procedure（10 步）

1. 收概念/命题/题材 → 格式路由（体量四选一）→ **AskUserQuestion 问输出位置（输出位置协议）** → 导演确认
2. **A 种子期**（**引导式追问，13 轮逐轮等用户回答**）：愿望清单 → 八象/六变一常 → 前提句草案（只组合用户材料，交用户改）→ 三追问 → 低入口验收 → 私生人物 → 场域 → 欲望分层/生长主路 → 值得写 → 尺度 → 入口 → 冬至暗动 → 样片 → 前置门预检（低入口/生成力/暗动）
3. **B 世界生成期**：硬规则 6 + 历史压力 5 + 推导七步 → 主角缺憾-世界缺憾关联 → 样片 → 质量门 11 预检
4. **C 人物生成期**：八步操作法 → 五组问题清单（38 问逐人填写）→ 执四形态与阶段变化 → 能力矩阵 + 扑街十问 → 样片 → 质量门 1-10
5. **D 结构期**：命运大纲十二问 → 叙事大纲（含信息分配七选一）→ 时位细纲（三线 + 支线将位接入）→ 二十四节气逐条对照 → 样片 → 质量门 12-17/19/20
6. **E 载体翻译期**：章纲七要素 → 场/幕 → 场景卡 → 节拍表 → 剧本正文 → 剧本硬规则检查 → 样片 → 质量门 18 + 硬规则（动作≥40%/对白≤3/无不可拍词）
7. **F 表演层注入**：角色内在/表演心理学/微表演/否定约束（引用 07）→ 回填剧本 → 样片
8. **G 余震期**：大雪 gate + 冬至 gate + 归藏检验 + 余震三问 → 样片 → 质量门 16 复核
9. 产出剧本包（场景卡/节拍表/剧本/表演层）→ 03-09 生产链照接
10. 最终签核：全部阶段四态声明完整 + director-log.jsonl 完整（rationale 均非空）→ 剧本离开本协议

## Failure Protocol

| 条件 | 动作 |
|------|------|
| 无 logline 或五秒检验不过 | FAIL，退回 A 重做概念组合 |
| 世界推导七步缺任一步 | FAIL，B 未完成 |
| 五组问题清单有角色空答 | FAIL，人物未建立（质量门 1） |
| 执代价落在无辜者但伤害未显形 | 红牌，回 C 补显形载体 |
| 剧本出现"她感到/意识到/记得" | FAIL，不可拍词（E 硬规则） |
| 动作占比 < 40% 或对白 > 3 句 | FAIL，E 格式门 |
| 大雪 gate 没过（结尾像续集钩子/解释干净） | FAIL，回 G 重写余震 |
| 缺 director-log.jsonl 或 rationale 空 | FAIL，签核不完整，剧本不得离开本协议 |

## Anti-Patterns
