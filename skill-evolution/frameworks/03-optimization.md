# 03 — 优化提案（提案格式 / diff 纪律 / 用户裁决）

> 本文件是 SKILL.md「流程③④ 优化提案与应用」的操作细则，不独立成立。

## 一、提案格式

每条提案必填 6 字段（缺任一 = 提案不完整，不进裁决）：

```
### 提案 N：<一句话改动>
- 目标文件：<skill 内具体文件路径>
- 改动内容：<精确到节/段的改动描述>
- 依据信号：<引用 01 扫描的信号编号/证据——无依据的提案不成立>
- 影响面：<影响的 skill 交互/下游流程/其他 skill 引用>
- 改动成本：<低（几行）/中（一节）/高（整文件重写）>
- 候选方案：<AI 提议 2-3 个做法，各带取舍>（用户裁决的依据）
```

## 二、AI 提议、用户裁决（与共创模式一致）

- **AI 充分参与**：每案给 2-3 个候选方案（保守/均衡/激进），AI 标注自己的推荐与理由——不把决策负担全抛给用户，也不替用户拍板
- 用户裁决方式：选候选 / 合并修改 / 否决（否决 = 信号降级为软偏好，重看证据）
- 批量提案按影响面排序：先交互可见的（用户马上感受到），后内部结构（文档/格式）

## 三、diff 纪律

- 应用前出示 before/after 摘要（改动节 + 原因）
- 散文文件节级改动，不整文件重写（除非整文件重写是候选方案且用户批准）
- 遵循目标 skill 的结构约定：frontmatter 完整性、理论出处标注、可判定检查、Files 表同步——改了正文不更新 Files 表 = 提案未完成

## 四、应用后

1. 验证：目标 skill 的引用不断链（grep 关键路径）；frontmatter 合法（name 与目录一致）
2. 涉及 novel-skills 仓库的 skill：同步 `G:/AI/Claude-Workspace/novel-skills/` 并 commit + push（代理 `127.0.0.1:7890` + `$env:GH_TOKEN = gh auth token`）
3. 复盘报告（输出位置协议）追加"已应用改动"清单
4. 更新 memory（MEMORY.md 索引）——如果有跨会话事实变化

## 五、防退化

- 一轮提案上限：≤5 条（聚焦最重的信号；信号多时先砍重复）
- 不因优化而破坏已验证的行为（"没坏别修"）：已由用户验收过的部分，无新信号不动
- 每条提案都能指出"用户会感知到什么变化"——感知不到的优化不做
