# 02 — 风格档案（维度结构 / 更新规则 / 引用方式）

> 本文件是 SKILL.md「流程② 风格档案更新」的操作细则，不独立成立。档案本体为 `profile.md`（本 skill 目录内的学习成果库）。

## 一、维度结构

profile.md 按五个维度组织，每条记录格式：

```
### <维度>
- **条目**：一句话偏好（具体、可执行）
  - 证据：<原话引用/行为>（时间）
  - 强度：硬偏好（显式声明/多次一致）| 软偏好（单次/倾向）
  - 状态：生效中 | 已被新偏好覆盖（覆盖者：条目名）
```

### 五个维度

| 维度 | 记什么 | 示例 |
|------|--------|------|
| 理论偏好 | 方法论来源倾向、理论优先原则 | "方法论必须来自自著理论（人物篇/命运篇/天演论），外来框架只借骨架" |
| 交互偏好 | 对话方式、界面选择、共创模式 | "选择框（AskUserQuestion）呈现选项；AI 提议用户裁决；中文唤起" |
| 质量偏好 | 对产出的质量要求 | "打分要有范畴标准（先落档再给分）；结论可追溯到理论条目" |
| 文档习惯 | skill/报告文件的写法偏好 | "双语标题；理论出处标注；可判定检查；Files 表" |
| 交付习惯 | 产出落点、报告、记忆、git 行为 | "产出不落 skill 目录（输出位置协议）；报告到 tasks/reports/" |

## 二、更新规则

1. **新信号进档案**：每次复盘把扫描出的风格信号并入对应维度；已有条目被新信号强化时更新证据与时间
2. **覆盖规则**：新偏好与旧档案冲突时，新信号覆盖旧信号并标注"已被覆盖"（用户偏好会进化，不静默删除）
3. **强度门槛**：≥2 次一致信号或用户显式声明 = 硬偏好；单次 = 软偏好（软偏好不驱动 skill 改动，只记录）
4. **每次更新**：档案顶部记"最近更新：<日期> <依据哪轮复盘>"

## 三、引用方式

其他 skill 执行时如何用风格档案：

- 执行前可读 `skill-evolution/profile.md` 的交互偏好维度——按用户偏好的方式交互（选择框/共创/中文）
- 设计产出时参考质量偏好与文档习惯——不另起炉灶
- **档案是参考不是铁律**：具体轮次以用户当场指示为准（档案滞后于用户的最新偏好）

## 四、档案 vs memory-curation 的边界

| 内容 | 归属 |
|------|------|
| 用户偏好/风格（怎么写、怎么交互、怎么交付） | 风格档案（本 skill） |
| 项目状态/决策/接力信息（这个项目干到哪、决定过什么） | memory-curation（current-state/decisions/handoff） |
| 跨会话事实（Foundry 约定、skill 中文名、GitHub 仓库） | Claude-Home memory（MEMORY.md 索引） |

复盘发现的跨会话事实（如"输出位置协议已写入四个 skill"）交给 Claude-Home memory 维护；项目决策交给 memory-curation；用户风格进档案。
