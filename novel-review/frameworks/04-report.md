# 04 — 诊断报告格式细则

> **理论来源**：报告结构综合自《人物篇》《命运篇》《天演论》的判定标准与 Foundry 导演模式（样片摘要/裁决日志）的决策简报格式；问题条目要求"理论依据可追溯"是本协议的原则（见 SKILL.md Core Thesis）。
>
> 本文件是 SKILL.md「诊断报告格式」的操作细则，不独立成立。

## 一、问题条目 schema（每条必填 6 字段）

```
#### 🔴/🟡/💡 <症状一句话>
- 位置：<章节/段落/人物>（精确到可定位）
- 理论依据：<理论条目>（附出处文件路径，如：《命运篇》失候清单·"该杀的时候舍不得断" → novel-original-writing/frameworks/03-structure.md §三）
- 证据：<原文引用 + 行号/段落定位>（无证据不得成条，见 00-scan.md §二）
- 为什么是问题：<按理论解释后果——读者侧/人物侧/结构侧会发生什么>
- 修复方向：<1-2 句具体做法，可指向对应原创流框架的操作（如"回 C 补执的来路"）>
```

字段缺任一 = 该条不完整，不得进入报告（与裁决日志 rationale 必填同理：**理由缺失 = 诊断未完成**）。

## 二、严重度定级规则

| 级 | 判定 | 处置 |
|----|------|------|
| 🔴 红牌 | 硬规则违反：失候 19 条命中 / 人物空答 ≥5 问 / 无辜者代价未显形 / 主角无不可逆 / 大雪 gate 未过（未落幕/追尽/钩子化）/ 退路被接回 / 主景无力 | 必修，编辑的第一优先 |
| 🟡 黄牌 | 原则未达：空答 2-4 问 / 执无来路 / 涟漪 2/3 缺失 / 信息分配换档无理由 / 盆景单问命中 / 归藏三查任一否 | 需修，排在红牌后 |
| 💡 建议 | 火候/优化：时位可更准 / 可借景 / 疏密微调 / 对白可压缩 | 可改可不改 |

定级冲突时取高：单条问题同时命中红牌与黄牌条款 → 红牌。同类问题合并成条（如"3 个角色都有执无来路"合成一条红牌，不拆三条）。

## 三、报告结构

```
## 小说理论诊断报告：<作品名>

### 总评（3-5 句）
<哪层成立、最严重问题是什么、整体修什么优先>

### 问题清单（红牌 → 黄牌 → 建议）
[条目按 schema]

### 层汇总表
| 层 | 红牌 | 黄牌 | 建议 | 一句话结论 |
|----|------|------|------|-----------|
| 人物 | n | n | n | … |
| 结构 | n | n | n | … |
| 结局 | n | n | n | … |
| 文笔 | 不设 | n | n | … |

### 天演评分（W 值）

七参数表（参数/得分/判据一句/证据）+ W 综合 + 档位 + 公式评语 + 三大定律（格式见 `05-score.md` §五）。

**评分-诊断联动（硬规则）**：
- 参数分 ≤3 ↔ 对应层至少一条红牌（M≤3 ↔ 结构层红牌；V/T≤3 ↔ 人物层红牌；ξ≤3 ↔ 结局层红牌）——对不上 = 打分或诊断有一方撒谎，回查
- 参数分 4-6 ↔ 至少一条黄牌（同层）
- W 档位为「差/劣」时，总评必须说明"为什么还能/不能救"（哪项在救：通常 T 或 ξ 高可以救 R/S）

### 修复优先级（可选，报告后交互选择「出修复方案」时产出）
1. <红牌条目按"影响下游条数"排序>
2. …
（每条：改什么/改后如何复核——复核用原诊断表重扫该条）
```

## 四、报告纪律

1. **总评先说成立的层**：评审不是只挑毛病——先确认"这部小说在哪层是好的"，再谈问题（防止误杀，也符合理论"对景互文"的视角）
2. **结论可追溯**：每条理论依据必须能指到理论文件的具体条目；指不到 = 该条降为"建议"或撤回
3. **修复方向指向操作**：能用原创流框架的操作表述就用（"回 C 补执-1 旧答案"），不能泛泛"加强人物"
4. **片段扫描的降级标注**：报告开头注明扫描模式（全文/片段/大纲/单层），片段与大纲模式的局限随报告明示
5. **数量上限**：单次报告红牌 ≤ 8 条、总条目 ≤ 20 条（超出 = 合并同类，聚焦最重的）
