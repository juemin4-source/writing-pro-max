# 00 — 扫描总纲（路由 / 证据采集 / 扫描顺序）

> **理论来源**：诊断标准全部来自用户自著《人物篇》《命运篇》《文学天演论》，其操作化版本已固化在 novel-original-writing 的 frameworks 中——本文件及各扫描表**只引用路径，不复制内容**。
>
> 本文件是 SKILL.md「诊断流程」的操作细则，不独立成立。

## 一、路由

| 输入形态 | 路由 | 各层可用性 |
|---------|------|-----------|
| 全文 ≤ 5000 行 | 全文扫描 | 人物 ✅ 结构 ✅ 结局 ✅ 文笔 ✅ |
| 章节片段 | 片段扫描 | 人物 ✅ 结构 ⚠️（只判局部时位，不判全书周期）结局 ⚠️（缺结尾时只审"归藏设计"）文笔 ✅（只对给定段落跑八查） |
| 大纲/细纲 | 大纲扫描 | 人物 ⚠️（只审可答性）结构 ✅ 结局 ✅（审设计不审文本）文笔 ❌（无正文，标注"文笔层跳过"） |
| 指定维度 | 单层扫描 | 只跑所选层 |

## 二、证据采集规则（评审的纪律）

1. **每条问题必须带原文证据**：引用原文 + 行号/章节号（`CH03-LN567` 或「第三章·第二段」）；片段输入无行号时引用段落首句定位
2. **反推法**：诊断标准是"人物/结构应该有什么"，从文本**反推**——推得出 = 成立，推不出 = 洞（问题）。记录"试图推哪一问、在哪一段推不动"
3. **证据优先于印象**：先找证据再定问题；找不到证据的"感觉不对"降级为建议，不得升红牌
4. **每条问题给严重度**：红牌（硬规则违反）/ 黄牌（原则未达）/ 建议（火候）——判定边界见 SKILL.md「严重度分级」
5. **修复方向必填**：只列问题不给方向 = 报告不完整

## 三、扫描顺序

```
层 1 人物 → 层 2 结构 → 层 3 结局 → 层 3.5 文笔
（结局层依赖前两层的"已/涟漪"结论——先扫完人物层再扫结局层，跨层复核才成立；
文笔层在最后跑，用现场八查复核各层证据的落地形态）
```

每层扫描产物：该层的诊断表（勾选 + 证据 + 问题草稿）。各层汇入 `04-report.md` 的报告格式。

## 四、防误诊

- 片段扫描**不判全书**：只报告"这一段落的时位问题"，不写"全书春发"式结论
- 文笔/语言问题由**文笔层**诊断（06-prose.md 现场八查，判据《文学天演论》第六部「现场」）：文笔不判"好不好看"，判"时位有没有落成现场"；文笔不生成红牌（红牌保留给理论硬规则）；文笔问题同时构成理论问题时记入对应理论层，文笔层作证据
- 类型差异：商业爽文与文学向作品的"欲望/执"深度不同——按作品自身承诺的类型标准判（logline 无从考证时按文本实际承诺判）；文笔判断同样按类型承诺判（喜剧的闲笔是风格，文学向的留白是风格）
